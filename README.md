# Flypaper

Flypaper — набор Python-скриптов и локальная веб-страница для наблюдения за
самолётами около Санкт-Петербурга и визуализации авиакомпаний. В проекте есть
три самостоятельных сценария:

1. **Live-страница:** получает ближайшие самолёты через FlightRadar24, рисует
   один выбранный самолёт на декоративной сцене и показывает сведения о рейсе.
2. **Загрузка ливреи:** скачивает изображение хвоста авиакомпании AirHex,
   удаляет с него водяной знак `PREVIEW` и может нанести очищенное изображение
   на шаблон киля.
3. **Сбор статистики:** периодически считает приблизительное время присутствия
   самолётов в зоне наблюдения и записывает итоги в CSV.

Сервер предназначен для локального использования: он слушает только
`127.0.0.1`. Для получения полётов и изображений нужен доступ к внешним
сервисам FlightRadar24 и AirHex. Веб-страница также может загружать шрифты,
библиотеку SunCalc и флаги с внешних сайтов.

## Требования и запуск

Используйте Python и установите зависимости из `requirements.txt`:

```powershell
python -m pip install -r requirements.txt
```

В частности, используются `FlightRadarAPI`, `curl-cffi`, `flydenity`,
`numpy`, `opencv-python` и `scipy`. `scipy` необходим алгоритму удаления
водяного знака.

### Запустить веб-страницу

```powershell
python server.py
```

Откройте в браузере <http://127.0.0.1:8765>. Остановить сервер можно
`Ctrl+C` в окне, где он запущен. Фоновый опрос полётов завершается вместе с
процессом сервера.

### Скачать и очистить логотип

```powershell
python downloader.py 1200 800 TB
```

Позиционные аргументы — ширина, высота и двухсимвольный код авиакомпании.
Допустимые размеры — целые числа от 1 до 2048. Код может состоять из букв и
цифр, регистр не важен. Результат будет сохранён в текущей папке под именем
`TB.png`.

### Удалить водяной знак у своего изображения

```powershell
python remove_preview.py input.png output.png
```

Чтобы сохранить промежуточные диагностические изображения, добавьте `--debug`:

```powershell
python remove_preview.py input.png output.png --debug
```

Файлы диагностики сохраняются рядом с `output.png`.

### Наложить ливрею на шаблон вручную

```powershell
python livery.py SU.png
```

Без `-o` результат сохраняется рядом со скриптом как `SU_out.png`. Пути к
изображению ливреи и шаблону могут быть абсолютными или относительными к
текущей папке; если переданный путь не найден, скрипт также проверяет папку
проекта.

### Вывести ближайшие самолёты в консоль

```powershell
python flights.py
```

Этот режим периодически печатает найденные самолёты, высоту, расстояние,
азимут и угол возвышения. Он не запускает веб-сервер.

### Собирать airtime.csv

```powershell
python airtime.py
```

Скрипт продолжает накопление с уже имеющихся данных и работает, пока процесс не
будет остановлен.

## Live-страница и поток данных

При старте `server.py` создаёт два параллельных процесса работы:

1. В фоновом потоке `poll()` создаётся клиент `FlightRadar24API` и примерно
   каждые 10 секунд обновляется состояние ближайшего самолёта.
2. `ThreadingHTTPServer` обслуживает запросы браузера на `127.0.0.1:8765`.

Клиентская часть в `index.html` раз в 10 секунд запрашивает `/api`. Если
самолёт найден, страница обновляет карточку и силуэт. Когда меняется ключ
самолёта (позывной, регистрация или IATA-код авиакомпании), применяется
переход с затуханием; при обновлении того же самолёта числовые данные
обновляются без смены сцены.

При отсутствии самолётов страница переключается в пустое состояние и показывает
`Clear sky`. После ошибки опроса сервер сохраняет последнее успешное состояние,
поэтому кратковременная ошибка FlightRadar24 сама по себе не очищает карточку.
Состояние изначально пустое до первого успешного опроса.

### Сцена и анимация

Страница представляет собой иллюстрированный постер, а не карту или
трёхмерную модель:

- градиент неба и положение солнца рассчитываются по времени и координатам;
- при доступной библиотеке SunCalc отображаются также Луна и её освещённость;
- при недоступности SunCalc используется встроенный расчёт положения солнца,
  а Луна скрывается;
- четыре SVG-слоя облаков создаются в браузере с помощью `bank()` и окрашиваются
  в зависимости от высоты солнца;
- звёзды создаются случайно при загрузке страницы;
- параллакс облаков, самолёта и хвоста реагирует на движение указателя или
  датчики ориентации устройства;
- силуэт самолёта движется по заданной диагональной циклической траектории
  длительностью 90 секунд. Это декоративная анимация: траектория не отображает
  реальную позицию, курс или скорость самолёта.

Для дальнего силуэта код типа `Aircraft.type` преобразуется в имя SVG-файла,
например `B738.svg`. Загруженные SVG кэшируются в памяти страницы. Если файл
для конкретного типа недоступен, клиент пробует силуэт по умолчанию `B738.svg`.
Если недоступен и он, ошибка выводится в консоль браузера.

Карточка показывает авиакомпанию/позывной, маршрут, города, тип или модель,
регистрацию, страну, высоту, скорость, курс и расстояние. Год производства и
серийный номер запрашиваются сервером, но текущая разметка карточки их не
показывает.

### Изображение хвоста

Для выбора ливреи страница использует двухсимвольный `airline_iata`. Если код
валиден, браузер сначала запрашивает `/plane-status/<CODE>.json`.

- Если изображение уже готово, загружается `/plane/<CODE>.png`.
- Если его ещё нет, браузер показывает `plane/empty.png` и запускает загрузку
  готовой картинки самолёта. Запрос `/plane/<CODE>.png` на сервере при этом
  скачивает хвост при необходимости, удаляет `PREVIEW`, применяет ливрею и
  возвращает итоговый PNG.
- Пока новая картинка не загружена, хвост остаётся скрытым или используется
  пустая картинка; при ошибке клиент переключается на пустой вариант.

Большое изображение хвоста и маленький силуэт самолёта — независимые элементы:
силуэт берётся из SVG, а крупный хвост — из результата композитинга с ливреей.

## Сервер и HTTP API

`server.py` задаёт порт `8765`, каталог кэша `tail-cache/` и общее состояние
`state = {"aircraft": None}`. Веб-сервер привязан к `127.0.0.1`; обращения с
других компьютеров по сети он не принимает.

Поддерживаемые GET-маршруты:

| Маршрут | Ответ |
| --- | --- |
| `/` и любой путь, не совпавший с отдельным маршрутом | `index.html`. |
| `/api` | JSON-состояние с полем `aircraft`: объект выбранного самолёта или `null`. |
| `/aircraft.svg` | Статичный SVG `B738.svg`. |
| `/shapesSVG/<TYPE>.svg` | Силуэт с указанным кодом из `shapes SVG/`; если файла нет — 404. |
| `/plane/empty.png` | Локальная пустая картинка. |
| `/plane-status/<CODE>.json` | JSON вида `{"available": true}` или `{"available": false}`. |
| `/plane/<CODE>.png` | Скомпонованное изображение хвоста; может инициировать загрузку и рендеринг. |
| `/tail/<CODE>.png` | Загруженное и очищенное изображение AirHex без наложения на шаблон самолёта. |

В шаблонах `<TYPE>` разрешены 1–4 заглавные буквы или цифры, `<CODE>` —
ровно две заглавные буквы или цифры. Коды приводятся к верхнему регистру на
клиенте/в загрузчике.

`get_tail()` сначала проверяет `tail-cache/<CODE>.png`, затем загружает
изображение через `download_airline_tail()`. Для одного кода используется
блокировка, чтобы параллельные HTTP-запросы не загружали его повторно. Запись
проходит через временный файл и `os.replace()`.

`get_plane_image()` применяет `livery.apply_livery()` к `template_tail.png` и
загруженному изображению. Результат сохраняется как `plane/<CODE>.png`.
`plane_image_is_cached()` проверяет, что файл существует и не старше исходного
изображения хвоста, шаблона и `livery.py`. Для рендеринга тоже есть блокировка
на код авиакомпании и конфигурацию самолёта.

При проблемах загрузки или создания изображения соответствующие маршруты
возвращают HTTP 502 и печатают описание ошибки в консоль. Ошибка запроса SVG
возвращает 404. Остальные успешно обработанные ответы получают
`Cache-Control: no-store`, чтобы браузер не закреплял устаревший ответ.

## Получение и обработка полётов

### Настройки области

В `flights.py` заданы:

- центр: широта `59.938744`, долгота `30.314166`;
- радиус: `75 000` метров;
- базовый интервал опроса: 10 секунд;
- максимальный экспоненциальный интервал после HTTP 429: 15 минут.

### Модель данных `Aircraft`

`Aircraft` — dataclass, общий формат результата для `server.py`, `flights.py`
и `airtime.py`. Он содержит:

- `callsign`, `type`, `registration`;
- `airline` (ICAO) и `airline_iata`;
- аэропорты `origin` и `dest`, города `origin_city` и `dest_city`;
- модель, год выпуска, серийный номер и возраст;
- страну и ISO alpha-2 регистрации;
- `alt_m` — высоту в метрах;
- `speed_kt` — путевую скорость в узлах;
- `dist_m` — расстояние от центра области в метрах;
- `bearing` — азимут от центра области до самолёта;
- `heading` — курс самолёта, если он известен;
- `elevation` — угол над горизонтом от точки наблюдения.

### `fetch_nearby()`

Функция получает границы области от FlightRadarAPI, загружает самолёты,
отбрасывает находящиеся на земле и создаёт `Aircraft` для остальных. Затем
результат сортируется по `dist_m`, от ближайшего к дальнему.

Расстояние вычисляется формулой гаверсинуса (`haversine()`), направление —
`bearing()`. Высота из источника переводится из футов в метры с коэффициентом
`0.3048`. Курс сохраняется только при конечном числовом значении; иначе он
становится `None`. Угол возвышения рассчитывается как
`atan2(высота, расстояние)`.

Для первого самолёта в отсортированном списке при необходимости запрашиваются
дополнительные детали вызовом `aircraft_profile()`. Дополнительный вызов
выполняется, если регистрация отличается от предыдущей или изменился маршрут,
переданный сервером. Детали включают сведения из объекта самолёта и
FlightRadar24-ответа аэропортов; возможные имена полей года и серийного номера
перебираются как несколько вариантов. Если запрос деталей не удался, ошибка
печатается, но базовые данные полёта сохраняются.

### Определение страны регистрации

`registration_country()` последовательно пытается определить страну:

1. Разбирает регистрацию при помощи `flydenity.Parser`.
2. Использует известные числовые ID FlightRadar24 (в текущем словаре явно
   перечислены Китай и Турция).
3. Ищет регистрацию по таблице распространённых префиксов, например `RA-`,
   `TC-`, `A6-`, `N`, `G-`, `JA`.
4. Если остался только неизвестный числовой ID, возвращает подпись
   «Неизвестная страна (код: ...)».
5. Если определить ничего нельзя, возвращает пустые значения.

### Повторные запросы при HTTP 429

`is_rate_limited()` определяет ограничение частоты по коду 429 в HTTP-ответе
исключения. `poll_delay()` использует заголовок `Retry-After`, если он
присутствует: понимает секунды и HTTP-дату. Если заголовок отсутствует или его
не удаётся разобрать, задержка растёт экспоненциально и ограничивается
15 минутами.

## Логотипы и удаление PREVIEW

### `downloader.py`

Скрипт формирует URL AirHex по коду авиакомпании и требуемым размерам, делает
HTTP-запрос `curl_cffi` с браузерной имитацией и таймаутом 30 секунд. Он
проверяет `Content-Type`, декодирование и фактические размеры изображения.
Загрузчик работает в памяти и не создаёт промежуточный входной файл. Если
сервер вернул корректное изображение с неуспешным HTTP-статусом, код выводит
предупреждение и всё же продолжает обработку.

Публичная CLI-функция принимает размеры в диапазоне 1–2048 и код длиной ровно
два ASCII-символа, состоящий из букв или цифр. Выходное имя строится из
верхнего регистра кода.

### `remove_preview.py`

Алгоритм рассчитан на изображения с известным типом водяного знака: наклонная
полупрозрачная полоса шириной около 150 пикселей и надпись `PREVIEW`. Положение,
цвет и прозрачность не заданы заранее — они оцениваются отдельно для каждого
изображения. Параметры масштабируются относительно базового размера 600
пикселей по большей стороне.

Обработка выполняется в premultiplied RGBA: компоненты цвета предварительно
умножаются на альфа-канал. Для полупрозрачного наложения используется модель
смешивания вида `наблюдаемый цвет = слой + (1 - прозрачность) × исходный цвет`.
После оценки параметров алгоритм обращает это смешивание.

Порядок работы:

1. `load_image()` декодирует PNG/JPEG из пути или байтов, переводит BGR(A) в
   RGB(A), нормализует значения и формирует premultiplied-представление.
2. `find_band_coarse()` перебирает угол в диапазоне 25–65 градусов и ищет две
   параллельные границы с перепадом на значительной части длины.
3. `edge_pairs()` выбирает пары точек по разные стороны границы только там,
   где соседний фон достаточно однороден.
4. `fit_overlay()` оценивает цвет и непрозрачность полосы методом RANSAC с
   последующим МНК-уточнением.
5. `refine_band()` оценивает точное покрытие краёв полосы внутри пикселей и
   уточняет угол и положение через `scipy.optimize.least_squares`.
6. `remove_band()` строит карту покрытия и снимает слой полосы обратным
   смешиванием.
7. `register_template()` совмещает шаблон букв с изображением по корреляции
   градиентов; затем положение уточняется на субпиксельном уровне.
8. `contour_samples()` выбирает чистые пары «буква/фон», а `fit_overlay()`
   оценивает параметры текстового слоя.
9. `remove_text()` удаляет надпись и отдельно уточняет покрытие сглаженных
   краёв букв, чтобы уменьшить остаточный контур.
10. `save_image()` восстанавливает обычные RGB(A)-значения и сохраняет
    изображение, сохраняя исходное наличие альфа-канала и тип пикселей.

Вспомогательные функции выполняют геометрическое преобразование координат,
выборку пикселей с интерполяцией, оценку покрытия пикселя прямой и построение
диагностических изображений. При `--debug` создаются карта покрытия полосы,
изображение после её снятия, матта текста и картинка совмещения шаблона.

`preview_template.png` — обязательный файл рядом с `remove_preview.py`.
`load_template()` читает его в градациях серого. Шаблон хранится в 8-кратном
разрешении, чтобы точнее оценивать сглаживание букв.

## Наложение ливреи на самолёт

`livery.py` преобразует исходный логотип в изображение киля на шаблоне:

1. `silhouette()` строит маску изображения: использует альфа-канал или
   отделяет объект от фона заливкой от углов.
2. `livery_quad()` находит контур логотипа, выпуклую оболочку и приближает её
   четырёхугольником; `order_quad()` упорядочивает углы, а `refine_quad()`
   уточняет стороны и их пересечения.
3. `bg_color()` оценивает доминирующий цвет внутри ливреи. Это позволяет
   заполнить фон логотипа, а не переносить в результат прямоугольный фон
   исходной картинки.
4. `apply_livery()` совмещает ливрею с килем перспективным преобразованием по
   четырём углам (`fin_quad`) либо преобразованием по передней кромке (`lead`).
5. Маска пересечения силуэта самолёта и полигона киля ограничивает область
   наложения.
6. Яркость базового шаблона используется для сохранения теней и линий на
   поверхности; белые элементы смешиваются с заданным кремовым цветом бумаги.

`PLANES` содержит конфигурации геометрии `tail` и `b738`. Веб-сервер выбирает
`tail`: шаблон `template_tail.png`, полигон киля и перспективное четырёхугольное
преобразование. CLI `livery.py` позволяет выбрать конфигурацию через `-p`,
путь к шаблону через `-t`, путь результата через `-o`, а направление носа
логотипа — через `--livery-faces left|right`. Для конфигурации `b738` обычно
нужно явно передать собственный шаблон, поскольку общий файл `template.png`
в проекте не поставляется.

`imread()` и `imwrite()` читают и записывают через OpenCV-кодеки и NumPy.
Такой подход используется для корректной работы с путями, содержащими
не-ASCII-символы в Windows.

## Сбор статистики airtime

`airtime.py` — независимая консольная программа. Она использует тот же
`fetch_nearby()` и запускает опрос с интервалом 60 секунд. Для каждого найденного
самолёта добавляется одна минута к паре ключей `(авиакомпания, тип самолёта)`.

- `airline_of()` использует ICAO-код авиакомпании; если он отсутствует,
  пробует взять первые три буквы позывного, когда за ними следует цифра, иначе
  записывает `?`.
- `load_names()` запрашивает справочник ICAO-кодов и названий авиакомпаний.
  Если справочник не загрузился, ошибка печатается, а сбор продолжается без
  названий.
- `load()` восстанавливает уже сохранённые минуты из `airtime.csv`.
- `save()` сортирует итоги по убыванию времени, пишет заголовок
  `airline,name,type,minutes`, сохраняет во временный файл и заменяет им CSV.
- Сохранение выполняется после успешного опроса, только если в зоне есть
  самолёты.

CSV создаётся рядом с `airtime.py`. Это оценка по периодическим снимкам, а не
точная запись времени нахождения каждого борта в зоне. Время, пропущенное во
время остановки скрипта или неудачных запросов, не интерполируется.

## Формат данных API

Ответ `/api` имеет верхнеуровневое поле `aircraft`. Когда самолёт не выбран,
оно равно `null`; иначе содержит сериализованный dataclass `Aircraft`.
Например, структура выглядит так:

```json
{
  "aircraft": {
    "callsign": "ABC123",
    "type": "B738",
    "registration": "N123AB",
    "airline": "ABC",
    "airline_iata": "XY",
    "origin": "LED",
    "dest": "XXX",
    "origin_city": "",
    "dest_city": "",
    "model_name": "",
    "year_built": "",
    "serial_number": "",
    "registration_country": "",
    "registration_country_iso2": "",
    "aircraft_age": "",
    "alt_m": 0,
    "speed_kt": 0,
    "dist_m": 0,
    "bearing": 0,
    "heading": null,
    "elevation": 0
  }
}
```

Значения выше иллюстрируют только форму данных, это не реальные сведения о
конкретном рейсе. Неизвестные текстовые детали обычно представлены пустыми
строками, неизвестный курс — `null`. Координаты самолёта намеренно не входят в
dataclass и в ответ `/api`.

## Ограничения и особенности

- FlightRadar24 может ограничивать частоту запросов или временно не возвращать
  данные. После HTTP 429 скрипты используют `Retry-After` или экспоненциальную
  паузу.
- Ближайший самолёт определяется только среди полётов в заданной области и
  самолётов, которые источник помечает как находящиеся в воздухе.
- Дополнительные детали запрашиваются только для ближайшего самолёта, не для
  каждого борта в списке.
- Если дополнительный профиль временно отсутствует, основные сведения о
  полёте всё равно используются; сервер при той же регистрации старается
  сохранить некоторые сведения из предыдущего ответа.
- Имена и наличие полей в ответах внешнего API могут меняться. Некоторые
  поля интерфейса поэтому могут быть пустыми.
- Live-сцена не является точным отображением реального курса, масштаба,
  положения или движения самолёта.
- Часть визуальных ресурсов страницы загружается с CDN: без доступа к нему
  внешние шрифты, SunCalc или флаги могут отсутствовать. Для солнца есть
  встроенный резервный расчёт, для Луны — нет.
- В `plane/` имеются локальные PNG с кодами авиакомпаний, а сервер также
  сохраняет сгенерированные варианты `plane/<CODE>.png`. При обновлении
  исходников или шаблона кэш считается устаревшим по времени изменения и может
  быть перегенерирован.
- Алгоритм удаления `PREVIEW` рассчитан на описанный шаблон водяного знака и
  соответствующий ему файл `preview_template.png`; это не универсальный
  инструмент удаления произвольных водяных знаков.
- Автоматические тесты в корневой структуре проекта не обнаружены.
